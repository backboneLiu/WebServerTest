## 一、背景（这不是编的，是 FDE 的日常）

客户 ERP 里有一套跑了 7 年的订单计价逻辑（`legacy/OrderPricing.cs`）。

现在要给客户上线一个 AI 报价助手，助手算出来的价格必须和 ERP **一分钱都不差**，否则客户财务会直接叫停项目。而客户的后端是 .NET，助手侧是 Python。

**你的任务：把这套逻辑等价地实现成 Python，并用测试证明它真的等价。**

> 这就是 FDE 最典型的第一个动作：**先把客户的既有行为搬到新系统，一个字节都不能变，然后才谈优化。**

> **如果 `uv sync` 卡住或慢得离谱**：国内直连 PyPI 常常只有几十 KB/s。挂国内镜像重试：

> ```powershell

## 五、三个陷阱（只提示，不给答案）

1. **C# 的 `decimal` 对应 Python 的什么？** 如果你顺手写了 `float`，第 12 条会给你答案。
2. **`MidpointRounding.AwayFromZero` 对应的不是 `round()`。** Python 的内置 `round` 是另一个策略。想清楚再写。
3. **`MaxDiscountRate = 0.30` 这个常量，永远不可能生效。** 最高档 12% + 最高阶梯 10% = 22%。发现它之后，**不要改它**——先想清楚：这是历史遗留，还是我算错了？记到 `notes.md` 里。

> 第 3 条是这次练习真正的考点。FDE 在客户系统里看到「多余」的代码，第一反应必须是**先记录，再求证**，而不是顺手优化掉——因为你不知道那行代码背后是不是有一条三年前的商务约定。
